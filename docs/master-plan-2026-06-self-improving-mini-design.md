## 0. North star

Two complementary training levers over ONE shared data rail (`.aspis-training/pairs.jsonl` + Censor verdicts as objective scorers):
- **ORPO** = trains WEIGHTS, local models only (Qwen via oMLX). Runs **nightly on the Mac** (mlx-lm-lora, QLoRA/QAT) — data never leaves the machine.
- **SkillOpt** = trains TEXT (`SKILL.md`) for FROZEN models (claude/codex/design) we can't fine-tune. Runs nightly via **SkillOpt-Sleep**.

The runtime loop: coder orders → **mini WRITES** (local Qwen, emit-edits → Rust applies, sandboxed, read-only Oracle) → **deterministic Censor** verdict → **mini fixes ONCE → stops** → **coder reviews** (Censor + Gemma tier + its own Sonnet review pass) → fixes → Kanban `review` → human-gated final reviewer. Every mini output is a reviewed draft. Four independent security layers (server allowlist, Seatbelt FS, Rust diff/revert guard, bounded loop).

Hardware: **Mac = inference (day) + nightly training (night) + data collection**. **Scaleway = only the heavy one-shot initial ORPO warmup.** No macOS 27 dependency anywhere.

## Cross-cutting rules (apply to every phase)
- **PRODUCT GENERALITY (added 2026-06-12 — the app is for EVERYONE, future name "Devboule", not an Aspis lab rig).** Every concrete value in this plan (oMLX at `127.0.0.1:8000`, Qwen/Gemma model names, the M1 Max, `.aspis-training` paths) is **the dev machine's default, never a product assumption**: server URL/port, provider kind (oMLX/Ollama/OpenAI-compatible API/codex), and model are all user-selectable from Settings (the cards already exist; keep it that way — no hardcoding endpoints or model IDs in new code, including the `chat_template_kwargs` fix: send it per provider capability/model family, not unconditionally). Provider auto-detection must find whatever the USER has installed ([[provider-autodetect-requirement]]). The whole self-improvement stack (nightly ORPO, SkillOpt, training capture) is **opt-in per user** and degrades gracefully: no local server → mini falls back to API/codex backends; no training data → nothing runs. Everything works on ANY folder/project with zero config ([[am-folder-agnostic-product]]), Mac AND Windows.
- cfg-gate Win/Mac; the Windows path stays byte-for-byte unchanged behind `#[cfg(windows)]`.
- Gates per phase: `cargo test --lib`, `npx tsc --noEmit`, `npx vitest run`, `python -m pytest oracle`.
- Privacy: loopback-only for oMLX/Gemma; `.aspis-training/` is gitignored (`*`); secrets redacted before any persist; training/SkillOpt data never leaves the Mac (nightly local).
- Each phase independently shippable + testable. 🟢 = LIVE-testable NOW with the downloaded oMLX Qwen (mini) + Gemma (Censor).
- **RUNTIME STATE OUT OF THE SOURCE TREE (added 2026-06-12, after the dev rebuild loop).** The app currently writes per-machine runtime state next to its cwd — `config.json`, `projects/` (agent sessions, briefs, `.oracle-server.json`) — which on macOS dev is `src-tauri/` and on Windows dev the repo root. This caused an infinite `tauri dev` rebuild→restart→server-respawn loop (every Oracle server spawn looked like a source change) and is wrong for the PRODUCT too: an installed app must not depend on a writable cwd. Mitigated in dev with `src-tauri/.taurignore` + gitignore; the real fix is to move all runtime state to the platform app-data dir (as `oracle-data` already does), keeping a cwd fallback only for portable/dev use. Schedule as a hygiene task before the first Devboule-branded release; cfg-gate nothing — same path logic both OSes via the existing data-root resolution.
- **Nightly ≠ every night (DATA-GATED).** Both nightly jobs (P13 ORPO, P14 SkillOpt) run ONLY when enough NEW data has accumulated since the last run — e.g. ≥ N fresh `{rejected,chosen}` pairs, OR a min-interval floor (whichever). Otherwise the night is SKIPPED. No wasted energy/compute on low-data nights. Persist a watermark (last-trained timestamp + new-pair count) under `.aspis-training/`. Realistically the mini won't produce thousands of pairs/day → training every few days/weekly, not nightly; SkillOpt (token-expensive) even less often.

## Phase 4 — Mini WRITE via emit-edits + allowlist guard 🟢
**Goal:** the local mini actually writes files — safely. **Design (locked):** the local model EMITS structured edits (JSON edit list); the **Rust executor validates vs the ordered file-set allowlist (N≤10) and APPLIES** them — the model never touches disk. Pre-image snapshot (`training_export::snapshot_blob`) before; post-write `git diff` guard in finalize (`mini_coder_executor.rs ~1410`) **reverts any out-of-scope change**. **Files:** `build_mini_prompt` (emit-edits contract), finalize (apply+guard), `mini_coder.rs`. **Reuse:** scratch root, snapshot_blob. **Allowlist hardening (added 2026-06-12 — the validator checks PATHS, not just names):** canonicalize every edit target and require it to resolve inside the project root AND match the allowlist; explicit tests for (1) `../` path traversal, (2) symlinked targets (edit lands through a symlink pointing outside the allowlist), (3) **APFS case-insensitivity** — `SRC/Main.rs` vs allowlisted `src/main.rs` must be decided deliberately (compare case-insensitively on macOS or canonicalize to on-disk case; an exact-match check silently passes/fails differently on Mac vs Linux CI). Note the residual risk honestly: allowlist bounds WHERE, not WHAT — malicious content inside an allowlisted file (e.g. a test that exfiltrates when run) is caught by the later layers (Censor, coder review), and P5's sandbox tests must therefore cover RUNNING the project tests, not just the write. **Test:** cargo (apply works; out-of-scope reverted; N>10 rejected; traversal/symlink/case tests above) — pure over a temp dir, no live model. **Deps:** P3. **Live:** Qwen mini writes a file in a throwaway project.

## Phase 12 — Vocab pruning of Qwen 27B (optional — DEFAULT: DON'T, revised 2026-06-12)
> **Bias strongly toward never doing this.** QLoRA on the 4-bit base with small batch + gradient checkpointing should fit 64 GB without it, and the cross-stack tokenizer-consistency burden (oMLX serving + scribe logging + training MUST share the trimmed tokenizer forever) is high. Trigger ONLY if P13 empirically hits the RAM wall — not preemptively.
**Goal:** shrink the ~150k multilingual vocab to coding+English → frees embedding memory so the nightly on-Mac ORPO (doubled activations) fits comfortably on 64 GB. **Do:** corpus/Unicode-based vocab trim → produce a trimmed MLX checkpoint that becomes the SINGLE tokenizer source of truth across oMLX serving + scribe logging + training (consistency is mandatory). **Do NOT:** depth-prune / ShortGPT — it collapses long-chain reasoning and SFT can't heal it (arXiv 2510.22228); the 4-bit quant is already the right compression. **Test:** parity eval before/after on a held-out coding set. **Deps:** none hard, but pairs nicely before P13. **Note:** the trimmed model is a checkpoint WE produce (not an HF download).

## Phase 15 — Fixed benchmark + promotion gate (shared by ORPO + SkillOpt)
**⏫ TIMING (revised 2026-06-12): build right after P6/P7, not just "before first training".** P15(b) is the DECISION TOOL for the plan's open questions, not only the deploy gate: run it on the candidates NOW to answer **MoE vs dense** (the P13 blocking decision) and **thinking on/off per call type** (the P1/P6 policy A/B) — both are cheap to measure once the harness exists and expensive to keep guessing.

**Goal:** after EVERY training run, objectively answer "did it help, and by how much" — and deploy ONLY if it strictly improves (never ship a regression). This is also the held-out validation SkillOpt REQUIRES and ORPO needs. **Two layers, both FROZEN + never trained on:**
- **(a) Standard open-source reference (don't reinvent — comparable, contamination-resistant):** CODING → **Aider-polyglot** (diff editing — closest to the mini's emit-edits), **LiveCodeBench** (fresh post-cutoff, contamination-resistant), optionally **SWE-bench Verified** (repo-level). DESIGN → **Design2Code** (Stanford SALT, 484 real pages; CLIP/CW-SSIM/TreeBLEU + Design2Code-Hard), **DesignBench**, **UI-Bench**, **WebGen-Bench**. Use as a sanity + regression signal only.
- **(b) OWN held-out set = THE metric that decides promotion:** a frozen slice of YOUR scribe pairs (coding) / YOUR design tasks (design), scored by YOUR deterministic gates — Censor verdicts + accept/redo (coding); the P11 objective gates tsc + tailwind-lint + DTCG token-match + axe + Playwright visual-regression (design). Reflects YOUR workload + YOUR contract, which generic benchmarks don't (per [[mini-coder-local-hardware-decision]]: the only trustworthy metric is accept-rate on your own tasks; the harness swings external scores 30-50 pts → reference-only).

**PROMOTION GATE:** run candidate vs current-deployed baseline on the SAME frozen benchmark with the SAME scorers; deploy the new adapter/skill ONLY if (b) strictly improves AND (a) doesn't regress. Mirrors SkillOpt's own validation gate — apply the same discipline to ORPO. Emit the delta (accept-rate, linter-clean %, design Tier-1 pass %) → consumed by P16. **Aesthetic caveat (design):** structure/tokens/a11y/visual-regression are objectively gatable; pure aesthetics stay LLM-judged (advisory). **Files:** oracle/ python eval harness; reuse Censor + design Tier-1 validator. **Deps:** P7 (data) + P11 (design scorers). **PREREQUISITE for promoting any P13/P14 output** (no benchmark → no deploy).
