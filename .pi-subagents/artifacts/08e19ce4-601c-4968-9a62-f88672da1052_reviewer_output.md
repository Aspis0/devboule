### Note

1. **Rule-name collision risk on PID wrap-around (windows.rs:313)**: The firewall rule name includes `std::process::id()` (broker PID, not child PID). If the broker process crashes without cleanup (e.g., power loss, `TaskKill /F`), the netsh rule persists. If a subsequent broker process later receives the same PID, `netsh add rule` will fail because the rule name already exists. The `?` on failure propagates this as a sandbox-spawn error. Mitigation: the broker PID is used only for uniqueness and Windows PID wrap-around is unlikely to collide with a stale rule in practice. A future hardening step could use a UUID or a cleanup-on-startup sweep of `devboule_sandbox_block_*` rules.

2. **Orphaned firewall rule on partial restore failure (windows.rs:438–442)**: In `wait_and_restore`, if `restore_path_policy` succeeds but `restore_net_policy` fails, `self.restored` is never set to `true`. However, both `self.acl_snapshots` and `self.net_snapshot` have already been consumed by `std::mem::take` (replaced with empty/default). The subsequent `Drop` sees `!self.restored`, attempts to restore again, but both snapshots are now empty — the firewall rule is orphaned. The error is returned to the caller, but the rule remains in the system firewall. A `Drop`-based safety net after a failed `restore_net_policy` cannot help here because the snapshot is already consumed.

3. **No C4-specific tests**: The test module (line 672) covers C1–C3 (token stubs, job object, ACL roundtrip) but has no tests for `apply_net_policy` or `restore_net_policy`. This is understandable — `netsh advfirewall` requires administrator privileges and mutates the system firewall. A CI-safe test would need to mock the netsh invocation or test on a dedicated Windows CI runner with admin rights. The tradeoff is documented in the commit message ("Real enforcement, testable" — testable by manual integration testing on a Windows machine).

4. **`netsh` requires administrative privileges**: The entire `netsh advfirewall` approach used in C4, like the `icacls` approach in C3, requires the broker to run elevated. This is an architectural constraint of the CLI-based sandbox strategy, not a C4-specific issue. Users running devboule without admin rights will see sandbox spawn fail on the first `netsh add rule` call.
